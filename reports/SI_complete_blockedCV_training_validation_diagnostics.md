## 2) Exact blocked CV method used in this project

### 2.1 Outer CV protocol (model evaluation)

The project uses **chronological expanding-window blocked cross-validation** via `sklearn.model_selection.TimeSeriesSplit(n_splits=3)`.

- No random shuffle.
- No leakage from future to past.
- Fold structure: training set expands, test set is the next contiguous time block.
- This is equivalent to a rolling-origin / forward-chaining evaluation pattern.

Evidence in code:

- `src/train_main_linear.py`
- `src/train_hgbr_optuna_v2.py`
- `src/run_linear_alarm_v2.py`
- `src/train_bcr_tcn_v11.py`
- `src/save_fold_predictions.py`

Evidence in exported split tables:

- `results/tables/blocked_cv_split_summary_H3.csv`

For H=5 specifically (from exported split summary):

- Fold 1: train 2021-02-03 to 2021-10-09, test 2021-10-10 to 2022-06-15
- Fold 2: train 2021-02-03 to 2022-06-15, test 2022-06-16 to 2023-02-19
- Fold 3: train 2021-02-03 to 2023-02-19, test 2023-02-20 to 2023-10-26

### 2.2 Inner validation protocol (inside fold training)

For BCR-TCN training, each outer-train block is split chronologically into:

- sub-train: earliest ~85% of outer-train,
- sub-validation: latest ~15% of outer-train.

Scaling statistics are learned from sub-train only and applied to sub-validation/test.

## 3) Why this blocked CV is methodologically defensible

This protocol is appropriate for forecasting/early-warning settings because it preserves temporal order and avoids look-ahead bias.

Recommended references to cite in SI:

1. Tashman, L. J. (2000). *Out-of-sample tests of forecasting accuracy: an analysis and review.* International Journal of Forecasting, 16(4), 437-450.
2. Hyndman, R. J., & Athanasopoulos, G. *Forecasting: Principles and Practice* (rolling-origin/time-series CV chapters).
3. Bergmeir, C., Hyndman, R. J., & Koo, B. (2018). *A note on the validity of cross-validation for evaluating autoregressive time series prediction.* Computational Statistics & Data Analysis, 120, 70-83.
4. Cerqueira, V., Torgo, L., & Mozetič, I. (2020). *Evaluating time series forecasting models: an empirical study on performance estimation methods.* Machine Learning, 109, 1997-2028.
5. Roberts, D. R., et al. (2017). *Cross-validation strategies for data with temporal, spatial, hierarchical, or phylogenetic structure.* Ecography, 40(8), 913-929.

## 4) Loss functions and training process

### 4.1 ElasticNet baseline

- Model: `ElasticNet(alpha=0.1, l1_ratio=0.5, max_iter=20000)` in standardized pipeline.
- Training per fold on outer-train, inference on outer-test.

Objective (conceptual):

$$
\frac{1}{N}\|y - X\beta\|_2^2 + \alpha\left(\rho\|\beta\|_1 + \frac{1-\rho}{2}\|\beta\|_2^2\right)
$$

### 4.2 HGBR baseline

- Model: `HistGradientBoostingRegressor` with Optuna-tuned hyperparameters.
- Outer blocked CV for hyperparameter selection and performance estimation.
- Uses internal early-stopping mechanism (`early_stopping=True`, `validation_fraction=0.1`).

### 4.3 BCR-TCN v1.1 (deep model)

Implemented in `src/train_bcr_tcn_v11.py`.

Composite training objective:

$$
\mathcal{L}_{total} = w_{reg}\mathcal{L}_{Huber} + w_{bce}\mathcal{L}_{BCE} + w_{rank}\mathcal{L}_{Rank}
$$

with configuration (H5 v2 meta):

- `w_reg=1.0`, `w_bce=0.6`, `w_rank=1.4`
- `grad_clip=1.0`
- optimizer `AdamW(lr=8e-4, wd=1e-3)`
- early stopping patience 25 epochs

Training/selection target for early stopping: maximize validation `Recall@5%` for `tau=16`.

## 5) Validation and evaluation logic

Evaluation is alarm-budget based:

- thresholds: `tau ∈ {15,16,17}`
- budgets: `r ∈ {0.05, 0.10}`
- top-`k` alarms where `k = ceil(r * n)`

Primary metrics:

- precision, recall, TP
- plus failure diagnostics exported here: FP, FN, TN, miss-rate, false-alarm-rate

Failure bars are generated from out-of-fold predictions for:

- `persistence_v2_H5`
- `enet_a0.1_l0.5_v2_H5`
- `hgbr_optuna_H5_v2`
- `bcr_tcn_v11_H5_v2`
- `hybrid_rank_ens_H5_v2`

## 6) Gradient vanishing/exploding diagnostics

### 6.1 What was exported

Using `src/si_export_training_diagnostics.py` (diagnostic replay, H=5, 3 blocked folds, max 60 epochs), we exported per-epoch gradient health:

- `results/tables/si_gradient_health_epoch_flags_H5.csv`
- `results/tables/si_gradient_ve_summary_H5.csv`

Definitions used:

- `is_exploding_risk = 1` if pre-clip gradient norm is very high (thresholded in script).
- `is_vanishing_risk = 1` if post-clip gradient norm collapses to very low values.

### 6.2 Quantitative findings

From `si_gradient_ve_summary_H5.csv`:

- Fold 1: exploding-risk epochs = 20/26 (76.9%), vanishing-risk = 0/26
- Fold 2: exploding-risk epochs = 27/29 (93.1%), vanishing-risk = 0/29
- Fold 3: exploding-risk epochs = 30/36 (83.3%), vanishing-risk = 0/36
- Mean clip fraction = 1.0 across folds

Interpretation:

- Raw gradients frequently reach large norms,
- gradient clipping (`clip=1.0`) is active and stabilizes updates,
- no evidence of vanishing gradients under the current rule.

This confirms that ranking preference can vary with operating point; SI should report this as policy-dependent behavior, not a single universal winner.
